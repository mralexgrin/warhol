Scout · PRD v1.3 · proposal, not a build

The data layer

Every trend in Scout is currently a sentence. This is the smallest set of marks that turns those sentences into graphics without breaking a single rule the PRD spent three grilling sessions locking down. Nothing here is wired to the prototype — it exists to be argued with.

Every proposal carries a handle (D1) so you can kill it by number. C1 is something computed, not chosen. P1 is a consequence for the PRD.

1The reading rule

Scout almost never has a curve. It has two points and a direction, reconstructed by Probe. The form has to say which — because a sparkline drawn through two known points invents the interior, and that is the same failure as an unverified absence.

Form declares evidence resolution D1

The reader learns to read how well we know this off the shape, without being taught. Almost everything is a slope. The sparkline is rare and earned.

one observation → a mark
two observations → a slope
many → a sparkline (watched only)
Rule no interpolation is ever drawn between points we didn't observe Source §5.3, §10.1

A graphic only draws a fact D2

Every non-fact is a sentence. Not found, doesn't apply, and tells us little here (citations at zero, #105) render as words — never a zero-height mark, because a zero bar claims we measured zero, which is a different and false claim.

The graphic sits in the line, not in a block D5

The report is already two-column — claim left, number right. Every mark goes in the right-hand column at text scale. Nothing gets a chart block and nothing gets a drawer, which is what keeps decision #82 intact: the report stays the card expanded. The fork (D7) is the single exception, and it earns it by replacing §6.2's Pressure lede rather than adding to it.

The principle that replaces it is stronger: no mark may ever be the only carrier of a fact. The sentence has to stand alone, which keeps §6.2's prose complete and makes the email version free.

2The marks

Six. One of them (the state mark) is a restyle of what v4 already draws. One of them (the fork) is genuinely new and is the one I most want you to attack.

The slope D6

Two dots and a connector. Hollow left dot is the past, filled right dot is now — so direction survives greyscale, print and forced-colors. The rise encodes sign and rough size, clamped at ±60%; the numbers either side carry the precision. This is the house form, because almost every claim in the product is was X, now Y.

The fork D7 renamed

Two slopes in one frame, each indexed to her own prior baseline = 100 — which is already how §5.2 defines cadence decay, so the shared unit exists in the model and no second axis is needed. Audience rises, output falls, and the gap between them is the thesis: growing faster than she can serve. §5.1 states this as a table and no screen has ever drawn it.

I called this "the crossing" in the write-up. It's wrong — both lines start at the same point and open rightward. It's a fork.

The tally D8

N ticks for we looked in N places. Each tick is a real check with a URL behind it in the check record, so it is countable rather than decorative — and it differentiates four places from eleven at a glance. This is the replacement for the confidence number §6.2 deliberately removed from the report: the detail is visible, so the percentage isn't needed.

It has to be taught, once. Ticks alone are a label that failed (§6.11 rule 1). So the first row that would use one states it in words instead — “not there · we looked in 6 places” — and every row below it carries ticks. That is §5.2's own move for weight: a clause on the top line only.

The state marks D9 D10

Three shapes, one size, so nothing implies weight (#92 holds — weight is order). Doesn't apply gets no mark at all, because §5.3 says it is not a verification state and it must not read as one.

D10 — hollow always means "this didn't happen." An absent inventory item and an expired-undecided card in the Decisions chart get the same treatment. One rule, two places.

Demand gets no graphic D11

Of the four sentences you named, three want marks. Demand isn't one of them — it's a count with two quotes, and a graphic for a single number is a one-bar bar chart. §6.2 already settled it: the audience is strongest as a number, the creator is strongest as a quote.

4The check-back

Watch is “a hypothesis with a date” (§5.8), so the check-back grades the bet. It is also the only surface where Scout has a real series.

5Decisions D20

The reframe that makes §12's trends screen buildable: this is the monthly re-check §5.4 already demands and never gave a home — “the threshold is read off a result, not chosen… re-check monthly once real data flows.” It is an instrument, not a scoreboard. That also settles the name: Trends would collide with creator trajectory. Decisions is plain, accurate, and still covers outcomes when they arrive.

Everything it needs is already instrumented

  • §10.3 — every decision is an event with actor, timestamp, verb, reason code and the score snapshot
  • §10.5 — state keyed on (brief_version, member, creator)
  • §6.4 — manual adds are source-tagged
  • §8 — outcome is an event, not a mutable field

No new collection. Same argument §6.10 makes for the check record — a read view over data that has to exist anyway. One exception, below.

The decisions ramp is ordinal, not categorical D15 C1

Promote > Watch > Pass is ordered by conviction, so it wants one hue stepping dark→light, not three identities. That also sidesteps a collision I found in the tokens: in dark mode --ok and --teal are byte-identical (#63C4AF), so a chart using v4's green Promote would literally be saying the gap is real about a decision.

Hue is lilac — Scout speaking about itself — which is exactly what this screen is. Steps validated against both surfaces; the light end had to be darkened twice to clear the 2:1 floor against white.

The hexes flip between themes — Promote is the darkest step on white and the lightest on the slab. The rule underneath is stable and is what the reader actually learns: most conviction = most contrast against the surface. Dark mode is stepped and validated separately, never an automatic inversion.

1 · What happened D17

Zero-result days appear as a marked series, not a dip — §5.4 says they're a feature, and a chart that reads them as failure teaches the desk the opposite of the doc. Expired-undecided is drawn hollow (D10) because it isn't a decision.

2 · Is the bar right

Score band against what the desk did. If they pass most of the 78–82s, the threshold rises. This is the calibration read, and it is the reason the screen exists at all.

3 · Why they said no

Pass-reason mix, ranked, single hue — one series, so no legend. “Not what I asked for” is broken out per brief because §6.7 acts on it at three.

4 · The outcome band D19

Outcomes need a year. Rather than hide that, the screen carries its own incompleteness as a designed state — the same ethic as “Scout found nothing worth your time today.” It fills up over the year and becomes a real chart.

6What this refuses to draw

Sourced from the doc, not from taste. Each one is a chart somebody will ask for.

  • No trendlines or projections — §12.1, quote and count, don't diagnose
  • No sparkline without observations behind it — §5.3, D1
  • No composite Trajectory index — §5.2, a fourth number is a fourth thing to learn
  • No confidence gauge on the report — §6.2 removed it on purpose; D8 is the replacement
  • No weight badge on inventory rows — #92, weight is order
  • No good/bad colour on a creator's own trend — §5.1, it inverts the model
  • No score-delta chart on the watchlist — §6.3 is explicit: quote the trend, never the delta
  • No creator leaderboard or ranking chart — §1, it is not a follower leaderboard
  • No revenue or value on any surface — §5.5, fabricated precision is the easiest thing to shoot at
  • No dual axis, ever — the fork indexes to a shared baseline instead

7Computed, not eyeballed

C1  --ok and --teal are the same hex in dark mode

Both #63C4AF in alloy.css. v4's green Promote button is therefore evidence-teal after dark. Harmless on a button; a defect the moment a chart uses it for a series. Resolved by D15 — decisions get their own validated ramp and never borrow a field colour.

C2  The fork's first draft failed in dark mode

Ink-as---text #F2F0F7 against butter #FFCF78 scores a normal-vision ΔE of 14.9 — below the hard floor of 15. Two pale lines a full-colour reader struggles to separate, and direct labels don't excuse it. I would have shipped that by eye.

P1  One consequence for the PRD

§4.6 says In Drop is computed, not stored — “you're in the drop if you cleared the gates and nobody has decided yet.” That's right as vocabulary, but it means how many names surfaced in March is not a stored quantity, and it's the x-axis of the first chart on the Decisions screen.

It is probably recomputable, since §7 already mandates as_of queries over append-only observations. But “probably” is doing work there, and the decided rows carry a score snapshot while the never-decided ones may not. Either §10 gains a line, or §12 accepts that month-over-month volume is a derivation that has to be verified before it's charted.
